# Concealed content and scratch interaction

The reusable `@atlas/markdown/concealment` component is a transient display surface for text, images and secret controls. It accepts a host callback, not the hidden payload. Before authorization, the DOM contains only synthetic skeletons and particles: no real text, image URL, ciphertext or hidden copy of the content. Import `@atlas/markdown/concealment/style.css` explicitly alongside the component or secrets plugin.

## Domain and trust boundary

- A concealed surface is a view, not a document node, storage format, cipher or access-control authority.
- The host decides whether existence may be disclosed. For an undiscoverable resource, do not instantiate the component; the server must omit its reference and metadata as well.
- `available` permits an interaction to ask the host to reveal. The host must authorize that request, perform any required MFA and audit, then supply a transient element. Returned content remains readable by the recipient after authorization regardless of its visual mask.
- `requestable` shows only a synthetic placeholder. **Password requests are visible at rest (owner decision 2026-09-28; the earlier hidden 850 ms hold is withdrawn for secrets):** the rail shows a one-line message (`labels.requestHint`, Czech „Hodnoty jsou skryté“) and a **Request access** button with a lock, in Reveal's place, before any interaction. Tab reaches the button directly (the surface itself has `tabIndex = -1`; Enter/Space on a focused surface moves focus to the button), and only the button's own activation starts a request. Blocks keep message and button on one line, stacking them where the ink is narrow and dropping the message below 19rem (it stays the surface's accessible name). Inline capsules carry the button inside the sentence after a short stretch of glitter; the idle message floats above on hover or focus. The follow-up states replace the message in place: sending, pending (`labels.pending`, „Žádost odeslána · čeká na schválení“, the button fades out), not approved (`requestRefused`, `labels.refused`, with the button for a new request) and a failed send (`labels.requestFailed`, the button stays). The surface exposes them as `data-concealed-request-state="idle|sending|pending|refused|failed"`. Ordinary (non-secret) requestable text and images keep the hold: hover dwell or holding a pointer, finger or Space/Enter for 850 ms agitates the specks more and more, then Request access slides in. Nothing ever automatically submits a request or grants access.
- Reduced motion stops travelling specks and the opening wave; the glitter still twinkles in place and lottery-ticket scratching stays available, because it is direct manipulation.
- For ordinary content, scratching may invoke the host loader. Password surfaces disable automatic scratch release: explicit reveal still invokes the existing host MFA/audit flow. Pointer movement is not an authentication factor.
- Authorized scratch interaction accumulates cleared regions like a scratch card. They remain clear during pointer/touch interaction; departure starts a default 1.5-second grace period followed by a slow 4-second cover in which the mist rolls back over the cleared path as one soft, randomly drifting front. The brush is large with a wide feathered edge; its radius follows the surface size slightly, between 44 and 110 px. Re-entry resumes the remaining cleared regions. Fine specks drift, twinkle and are reborn while visible. The ink itself stays calm at rest (a password request is announced by its visible button and message): only on hover or hold does it roll from its default colour into saturated red, with trembling specks and a large tilted "no" sign behind the glitter. A sent request slowly rolls the surface into blue with a background hourglass, also after a reload when the host reports `requestPending`. Reduced motion retains static feedback and direct keyboard access.
- `showRevealControl` is opt-in for ordinary text/images. Without the button, focus the surface and press Enter/Space to reveal; Escape clears immediately. Available secret surfaces always show an explicit Reveal control. Surface activation only focuses that button; the button's own click/keyboard activation invokes the host. Page/window visibility loss clears immediately.
- `reconcealAfterMs` controls the delay after departure before a 4-second cover. Omit it for the existing 1,500ms delay and 30-second inactivity guard; a finite number from 0 to 600,000 sets the delay, while `null` disables automatic covering for ordinary content. An explicit ordinary-content setting replaces the inactivity guard. Secret surfaces retain a 30-second inactivity limit (the mist then rolls back over 700 ms instead of snapping shut), and `null` cannot disable their default departure covering. Pending authorization remains bounded for all modes; explicit hide, abort, visibility loss and destruction always clear.
- Available secret surfaces keep no permanent buttons. Their actions (`ConcealedContent.actions`) slide in from the right on a soft veil on hover, focus or tap, and close on leave, focus loss or an outside tap. Once revealed, Hide takes the same right-hand place. A requestable secret is the exception above: its request and message stay in that rail at rest.
- Once a deliberate secret release returns an authorized transient element, its synthetic fog parts over 850ms as one invisible-ink ring expanding from a randomized inner origin; specks are swept onto a bright rim, with a few stragglers. No opening animation starts while authorization is pending or failed. Reduced motion replaces the ring with a gentle fade. The secrets document plugin releases into this surface too: its host returns elements for the shown fields. Hosts can call `reveal()` to release as if Reveal was pressed and `conceal()` to roll the mist back gently without moving focus.
- `completeRevealAt` (0.1–1, scratch only) lets the rest of the mist part on its own, as a ring from the stroke, once that share of the surface is scratched open; the share is measured on the fixed synthetic mask, never on the content.
- The pointer hands the specks momentum: pushed specks glide on with their own drag and settle elsewhere instead of springing back, and small, calm currents (about 4.5 px/s) carry neighbouring specks together. Surfaces without scratching (explicit Reveal, secrets) are stirred the same way without uncovering anything. With reduced motion both are off and specks only twinkle in place. Denied surfaces keep their resisting jitter.
- An uncovered inline capsule keeps no glitter rim, which would otherwise sit on the value; blocks keep their quiet six-pixel rim.
- Hide, page visibility loss, abort and destruction remove the supplied DOM and abort pending loads. A late returned element is disposed without insertion. The host is responsible for its own caches, object URLs and transport cancellation.

## Persistence model

The standalone surface adds no persisted shape. The separate secrets plugin stores canonical `secretId` references and non-sensitive presentation preferences; its schema v4 contract is in the [secrets plugin README](../../src/Atlas.Markdown/src/plugins/secrets/README.md#document-contract-schema-v4). Released secret values live only in host-created elements under this surface, never in the document. Ordinary text/image examples are isolated gallery fixtures. Securely wrapping an arbitrary document selection requires first moving the payload to an authorized server resource and replacing it with a reference; saving the plaintext inside a collapsed/blurred editor node does not meet this requirement. The optional [concealed content plugin](../../src/Atlas.Markdown/src/plugins/concealed/README.md) therefore offers only *visual* concealment (spoilers, quizzes, surprises) and is opt-in.

The surface accepts any authorized HTMLElement subtree, including a whole page section with headings, paragraphs, quotes and images. The gallery includes this larger case. The concealed content plugin wraps a selection like the blockquote command (bubble next to Quote, selected blocks, `/` Skrytý obsah): authors edit the content in an ink frame and readers see this surface over it. Its content stays in the document, Markdown and history. A future *protected* variant must instead move the section to host-owned protected storage and insert a reference only after that operation succeeds; history, collaboration, export and public projections must then be authorized/redacted at the server as well. A plaintext wrapper cannot provide that security boundary, which is why the visual plugin is opt-in and not part of the core editor.

4. Independent security review before calling this increment complete. This display component does not remove Atlas's existing server projection/collaboration rollout blockers.

## Resource bounds and verification

The gallery is `/?story=concealment`; the secrets integration is at `/?story=secrets`. The shared surface uses up to 6,000 synthetic specks depending on area, a fixed 512×256 accumulated mask stretched over the surface (created only once something is uncovered), a display canvas and one shared animation loop per document: a surface draws every frame (up to 60fps) for 10 s after an interaction, then over 5 s eases to 30fps and half of its specks, sleeping on a timer between draws; the next interaction fades them back in. Reduced motion twinkles in place at 30fps. A surface larger than the viewport (a whole concealed page) draws only a window of 1.5 viewports around it at full resolution; its specks keep their place on the page while it scrolls. Slower devices keep the frame rate and draw fewer specks instead: the ink starts with 35 % of its specks and, measuring each surface's drawing time, adds up to 30 % more every quarter second while all visible surfaces awake would stay well below 4 ms per frame, so a slow device never draws more than it can. A device that becomes busier later thins them again, down to 4 % on a page of hundreds of surfaces, never below a few specks each. Added specks fade in and extra ones leave only once faded out, so the density never changes in visible steps. Every canvas with pixels is a compositor layer, and hundreds of them slow each frame's commit and every re-layering of the page, so the document shares canvas pixels out: only surfaces within a viewport of the screen hold them, they get them in one batch for all surfaces within reach and lose them in batches once scrolling pauses. The colour clouds' animation exists only on surfaces someone has touched and is dropped far off screen. Typing in editable content (from its keydown until 800 ms after the last input) and a native drag hold the ink still without requesting frames, so it adds no keystroke latency; off-screen or hidden surfaces draw nothing. The background colour clouds drift only while the surface is hovered or focused. Accumulated clearing does not retain an unbounded pointer-event history. A completed touch hold preserves the request button after finger lift. Pending loads have a 30-second deadline by default; `revealTimeoutMs` (1,000–600,000) extends it for hosts that ask for a second factor inside `reveal`. Late results are disposed, and a release landing on a hidden page returns the surface to rest. On secret surfaces the status (copied, errors) sits in the right-hand rail and glides in with the buttons on hover, focus or tap, so it never covers the access sign; a requestable secret shows its request message there at rest. Secret surfaces never invoke automatic scratch release, including when the caller supplies `scratchToReveal: true`.

Verification covers synthetic-only covered DOM, explicit release, accumulated mouse/touch masks, delayed cover, pending access requests, lifecycle cancellation, inline schema migration, presentation settings, export omission and Atlas external-sharing guards. Run package unit/type/build checks, the packed consumer, gallery tests and `playwright.secrets.config.ts` after changes. Browser tests require local process permissions; Firefox desktop touch emulation and non-Chromium raw CDP gesture injection are unsupported and explicitly skipped. Independent review of the presentation component is not a production vault audit.

Keep ownership of each returned surface and call `destroy()` on unmount. Removing its DOM alone is not a substitute for unsubscribing its listeners/observers. After authorized content is issued, masks cannot prevent inspection or copying by that recipient.

Final checkpoint, 2026-09-25: 1,504 package tests, 4 gallery tests, package/playground typechecks, library build/declarations and offline packed-consumer imports/types/build passed. Browser coverage passed all 35 supported cases across Chromium, Firefox and WebKit; 4 unsupported touch/CDP combinations were skipped. The full browser run initially timed out replaying idle canvas frames in WebKit; the retention test now advances idle time without replaying every frame, while retaining full animation replay for covering, and its rerun passed in all three browsers. Atlas boundary/backup tests passed 63 with 7 PostgreSQL/SMB environment skips. Changed guard methods have 100% line/branch coverage and Slopwatch reported no issues. Independent reviews found no blocking issue in the reviewed component changes.

## Theming

The ink follows the host theme. Every value defaults to a mix of the shared design tokens (`--paper`, `--text`, `--accent`, `--amber`, `--red`), so editor themes such as `midnight` restyle it without configuration. Hosts such as Atlas wiki themes can override the public properties on `.md-concealed` or any ancestor:

| Property | Purpose |
| --- | --- |
| `--md-concealed-ink`, `--md-concealed-ink-deep` | Surface gradient under the glitter. |
| `--md-concealed-speck`, `--md-concealed-speck-shade` | Bright and shadow specks. |
| `--md-concealed-glint-1` … `--md-concealed-glint-3` | Colours of the rare four-point star glints. |
| `--md-concealed-denied`, `--md-concealed-denied-warm` | Warm tint, blushing edge and request colour without access. |
| `--md-concealed-veil` | Uncovered content background and the action-rail veil. |
| `--md-concealed-control-bg`, `--md-concealed-control-fg` | Glass pill buttons and status. |
| `--md-concealed-radius` | Corner radius. |

Canvas colours are resolved through the browser (including `color-mix()`) and re-read on resize, on a system colour-scheme change, when a surface is interacted with again and otherwise every five seconds (never while typing or dragging), so a live theme switch recolours visible glitter within a few seconds. Controls, status and the hold thread never appear abruptly; they fade or glide in. Hide sits outside the masked content in the corner (or in the right-hand rail position for secrets), so it works while content is only partly scratched.
