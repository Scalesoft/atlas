# Atlas web

Vue 3 frontend compiled into the .NET host. PostgreSQL and the HTTP API remain the source of truth. There is no mock backend and no required frontend web server.

## The editor package

The editor `@atlas/markdown` is the package `src/Atlas.Markdown` of this pnpm workspace (`pnpm-workspace.yaml`, dependency `workspace:*`); it came from its former repository with its history ([docs/markdown](../../docs/markdown/README.md)). Atlas imports its built `dist`, the same library build and declarations that used to be published: the Scalar reference and Monaco with its workers are bundled and emitted as lazy assets, never preloaded, and its only bare runtime import outside Atlas's existing peers is `yaml`, pinned in `package.json`. `pnpm install --frozen-lockfile` links it and installs its build dependencies into the same lockfile; `pnpm run build:editor` (`scripts/build-editor.mjs`) builds the dist when the editor's sources or the lockfile changed. `pnpm dev`, `scripts/build.mjs`, the test scripts, CI and `dotnet publish` call it, so run it by hand only before a bare `vitest` or `vite build`. The .NET server references the editor's library `Atlas.Markdown.Sync` (`src/Atlas.Markdown.Sync`) as a project.

Atlas installs the optional peers for the plugins it actually uses, including find/replace, invisible characters and code highlighting. Vue, Tiptap, ProseMirror and Yjs must be one copy for Atlas and the editor: the editor's devDependencies use Atlas's versions, and `src/editorBoundary.guard.test.ts` compares the resolved packages.

Change the editor in place, in the same commit as its use in Atlas; there is nothing to pin or release. Run pnpm for the editor from this directory, for example `pnpm --filter @atlas/markdown run typecheck` or `pnpm --filter @atlas/markdown exec vitest run --configLoader runner src/core`: inside `src/Atlas.Markdown` pnpm finds no workspace and would install it as a separate project.

Optional editor development with hot reload: `ATLAS_EDITOR_MODE=source` resolves the public `@atlas/markdown/...` imports from the editor sources `../Atlas.Markdown` (another checkout's editor package with `ATLAS_EDITOR_SOURCE`) for `vite`, `vitest` and `node scripts/build.mjs [--typecheck] [--package]`. `scripts/editorSourceMap.mjs` is the single list of public specifiers Atlas may import; `src/editorBoundary.guard.test.ts` fails when an import is missing from it, reaches `plugins/secrets` or concealment internals, when a listed entry is not exported by the editor package, when the built dist is older than the editor's sources, or when Atlas and the editor resolve a singleton to different copies. Entries Atlas may not import yet (currently none) are mapped only in source mode; elsewhere an Atlas stand-in from `unreleasedEditorFallbacks` reports the feature as absent. Source mode also mirrors the editor's own bundler aliases for Scalar and Monaco in the OpenAPI plugin and the shared source editor. Without the variable nothing changes: the built dist is used. `dotnet publish` fails while the variable is `source`: a published build always uses the built dist, and `pnpm run verify:editor --dist <wwwroot>` checks its OpenAPI assets. The only exception is the disposable browser-test build of `tests/browser/e2e-podman.ps1 -EditorMode source`, which opts in with `-p:AllowEditorSourcePublish=true`; never ship such an output.

## Checks and data contract

`pnpm test` tests a genuine rich-editor roundtrip containing YouTrack metadata and verifies that changing the appearance does not recreate the controller, lose content or reset undo. `dotnet publish` builds the frontend and places it in the published server’s `wwwroot`. Aspire runs Vite for development.

A standalone `pnpm run build` writes `src/Atlas.Web/dist`; `dotnet publish` passes `--outDir` pointing at the publish output's `wwwroot`.

The authoritative document is the complete versioned `atlas-rich` envelope in `contentJson`. Markdown is only a potentially lossy search/export projection. Invalid documents fail closed; they are never replaced by an empty fallback. Saving is explicit and uses `expectedVersion`; a failed/conflicting save leaves the local editor intact. Appearance previews do not remount the editor. Fullscreen search calls the server, cancels stale requests, renders snippets as text and returns focus when closed.

The application includes installation, builtin and configured OIDC login, spaces/pages, explicit draft save and publish, scoped search, personal appearance, and the actual YouTrack editor plugin. Wiki administrators manage local accounts and groups in Settings; space administrators manage scoped grants. Activation and administrator password reset display a short-lived one-use code for manual handover, never a password. The unauthenticated activation form consumes that code and returns to ordinary login. Codes and passwords are not persisted in browser storage or included in application URLs.

Profile is a routed workspace page at `#/profile/account`, with `security`, `visits`, `appearance` and `api` tabs. Opening it keeps the document editor mounted, including its content, undo and dirty state. Back navigation and tab changes respect pending operations and unsaved drafts, including an unacknowledged one-time API token. Appearance preview changes CSS without recreating the editor.

Account details use cookie-authenticated `GET`/`PUT /api/profile/account`; mutations include CSRF protection and the opaque account version. The editable email is contact data, never an authentication key. Authentication timestamps can be null for legacy sessions. Security supports changing a current builtin password and explicitly linking a configured external identity after server-validated proof. It does not auto-link by email. Without configured providers, the UI does not call unavailable OIDC identity endpoints. Account/group/access errors retain form drafts, and destructive access changes have an explicit cancelable confirmation. Server authorization remains authoritative even when a control is hidden.

## Editor integration

The host uses only public editor exports. `createEditorUploads` supplies image upload and the optional attachments plugin service; authorization, CSRF, limits and private download URLs belong to Atlas. Images are limited to 10 MiB and other attachments to 25 MiB. A persisted attachment carries `{ version, name, url, size, mimeType }`; readonly previews render that data without a metadata request. The picker and non-image drop use the same upload service. Mixed image/file drops report a one-file limit instead of silently dropping part of the selection.

The heading-anchors plugin persists stable IDs in rich content; the host supplies page URLs for copied heading links. `outline: { mode: 'floating', preview: false }` enables the optional outline. Changes to theme, layout and profile visibility preserve the editor instance.

Atlas selects `documentSchemaVersion: 2` and `allowOfflineEditing: false` on its public SignalR adapter. A disconnected editor locks until authoritative synchronization; pending updates remain in this window, with no reload recovery guarantee. The shared editor's default schema remains 1 and its default offline policy permits editing after hydration. Rich initial seeds preserve nodes such as attachments and tables; the server fences generations after restore and rechecks authorization before accepting mutations. Document durability, projection freshness and explicit page save/publish are separate states.

Configured OIDC and YouTrack services are managed by the server and administrator UI. Their real organizational configuration and migration data still need environment-specific acceptance; local fixtures do not certify external services.
