### Highlights
Pages open at once, you write straight into them and Atlas saves quietly.
- **Fast pages:** pages load and switch much faster, and even a long order page is ready for typing at once.
- **No switching:** whoever may edit a page clicks into the text and writes; the Edit and Save buttons are gone.
- **Quiet saving:** changes save themselves; instead of a button there is just Saving… and Saved.
- **Publishing per page:** each page is Manual, Automatic or Live; a draft in progress tints the top bar and says what readers see.
- **Discard changes:** unpublished changes go back in one step; the dialog asks at once and shows what will be discarded.
- **Clear history:** one session is one version with all its authors, switching between versions is instant and the arrows step through the changes.
- **Home and What changed:** after sign-in you land on Home, with the recent changes of the pages you may read.
- **Requirements as text:** a requirement is a heading with a state, chips and dependencies as links; you write into it like the rest of the page.
- **Deployment board as architecture:** an order's products side by side, their external services and connectors under them; “Arrange as architecture” tidies them.
- **Boards without Edit:** you write straight into texts, cards and page previews on a board, from the keyboard and by touch too.
- **Edit lock:** if you only want to read a page, lock it at the top right; in your profile you can choose to open pages read-only.
- **Czech and English:** the whole Atlas tool in your language; page content stays as written.

### Writing
- **No top toolbar:** formatting lives in the bubble above the selection, behind the slash and on the keys; the help lists them all.
- **Links:** text typed after a link is no longer part of it, a click into a link while writing only places the cursor, and a bar above the link offers Open, Edit and Remove link; Ctrl+click or the middle button opens it.
- **Cursor:** it glides as you type and blinks only when idle.
- **Undo by words:** one Undo step takes back one typed word, in shared writing too; the Undo button sits in the page's top left corner.
- **Blocks from the keyboard:** Tab walks a block's controls, Backspace and Delete select the block first, Esc leaves it selected and the block menu offers “Turn into…”.
- **Folding sections:** sections fold by their heading; the former disclosure block is now a heading with its text.
- **Timed list:** a list with a date and time; Ctrl+Shift+D converts any list.
- **Page link:** `[[` with no query offers the recent pages, this space first.
- **Page source:** more blocks are editable as Markdown (lists, tasks, requirements as a heading `## Title {#id state=…}`), and a locked block shows its whole text.
- **Smooth typing and dragging:** Enter, the slash menu and dragging a block respond without a stutter even on long pages; saving waits until you drop the block.

### Reading
- **Selection for readers:** selected text offers Copy and Copy link; code copies with one click.
- **No jumping:** blocks that are still loading hold their place at the right size.
- **Contacts:** contact cards are smaller and closer together, and the position is no longer repeated; the read-only card copies the phone and e-mail and shows where the contact is used.
- **OpenAPI:** the API documentation opens in a full-height dialog with one scroll bar, with a YAML tab beside it for editing; Esc returns the cursor to the block.
- **PDF:** a page shows whether its PDF is done and offers a manual download; the file name carries the export date and time.
- **Search:** page content comes first in the results, YouTrack last and only with issues that are really mentioned in Atlas.

### Requirements and orders
- **Converted for you:** existing requirement blocks turn into headings by themselves after the update; the original content stays in the conversion's backup.
- **Requirement comments:** a comment is a dated line in the requirement's history, visible at level M; Ctrl+Alt+M or Comment in the Ctrl+. menu adds one in a requirement.
- **Who:** the party is a property of the requirement; “Who” in the overview filters by party and the summary's bar opens its requirements.
- **Level of detail:** just three levels: None, S and M.
- **Services from the catalog:** Atlas fills a requirement's service from the catalog; the deployment board draws external systems from it.

### Finding your way
- **Page tree:** “Sort alphabetically” orders a tree level by titles; moving pages by dragging can be turned off in the profile.
- **Home in one click:** the logo leads Home; the Atlas version in the profile links to What's new.
- **Secrets:** the secret picker is a popover at the cursor like the editor's other pickers, not a dialog.
- **Trash:** a space's settings lead straight to its page trash.

### Administration and operations
- **Application logs:** under Wiki administration there is a readable server log with filters, a live tail and a download; a job run shows its own log.
- **Jobs:** the overview has a summary and flags overdue and stuck jobs; heavy jobs start only when nobody has typed for a minute.
- **Live without refreshing:** jobs, logs, backups and the PDF export update on screen by themselves.
- **The server saves by itself:** when the last person leaves a page, or nobody types for a while, the server saves the pending changes itself; nothing depends on whether the browser manages to send the last change.
- **Smaller pages:** a page is stored and sent without default values (the largest order page is 1.10 MB instead of 1.83 MB), and the next time it opens only what changed is downloaded.
- **Operations:** the production server no longer needs Node.js; collaboration runs directly on the server and PDFs are printed by Chromium.
- **No logic in the database:** no triggers or functions in the database; the application does everything.

### API, MCP and AI
- **AI writes live:** MCP, the personal API and the assistant write into pages as collaborators; you see the changes at once and the page's publishing decides.
- **API tokens have only Read and Write:** a write token edits pages live like a person, and the page's publishing setting (Manual, Automatic, Live) decides when readers see the changes. The former scopes Drafts, Publishing and Direct publishing became Write, so a token that used to write only drafts may now publish and move pages too. Never more than its owner may, though, and never in spaces excluded from AI.
- **History over MCP:** AI reads a page's history as a person does.
- **Deployment board over MCP:** `projector_compose_board` composes the board and with `arrange` arranges it too.
- **Tables:** tables that plain Markdown cannot carry (merged cells, lists in cells) are no longer lost in exports and AI tools.
